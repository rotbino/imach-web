# دیزاین رفرنس ۳ — iMatch «ابزار روز اول، شبکهٔ تدریجی»

> بستهٔ مرجع طراحی UX (۲ اکتبر ۲۰۲۶) — طبق بریف ۴۵ بندی «Evolution, not destruction»

این پوشه یک **مرجع طراحی ایستا** است و بخشی از بیلد Next.js نیست.
دیزاین ۲ (پوشهٔ `design-reference-2`) دست‌نخورده باقی مانده و هر دو همزمان موجودند.

## اصل حاکم

**«Network is not the prerequisite for value — it is the multiplier»**
iMatch از روز اول بدون شبکه هم ارزش دارد؛ شبکه و تطبیق هوشمند به‌تدریج ظاهر می‌شوند.

## مدل ارزش سه‌لایه

| لایه | چیست | مثال UI |
|---|---|---|
| ۱ — روابط من | کاربر خودش می‌آورد | «تأمین‌کنندگان من» / «مشتریان من» |
| ۲ — ابزار عملیاتی | از روز اول کار می‌کند | دفتر قیمت زنده، لیست خرید، کاتالوگ، RFQ |
| ۳ — کشف هوشمند | تدریجی و دلیل‌دار | «۳ تأمین‌کننده جدید برایت پیدا کردیم» + دلیل تطبیق |

## قواعد کلیدی پیاده‌شده

- **جداسازی رابطه/پیشنهاد**: «تأمین‌کنندگان من» و «پیشنهادهای iMatch» دو بخش مجزا هستند
- **صداقت بدون شبکه**: حالت خالی واقعی — «هنوز تأمین‌کننده‌ای برای این کالا پیدا نکردیم» + «وقتی پیدا شد خبرم کن»
- **Matching ≠ Advertising**: رتبهٔ مرتبط‌سازی مستقل از پرداخت؛ «نمایش ویژه» جدا و شفاف
- **دلیل تطبیق**: هر پیشنهاد با context — «چون برنج هاشمی را دنبال می‌کنی…»
- **دعوت روابط موجود**: شماره/لینک/WhatsApp/Telegram/QR — یک الگو، دو context (مشتری/تأمین‌کننده)
- **مرز CRM**: مشتریان = «آخرین خرید/درخواست/تعامل» — نه lead pipeline، نه task، نه ERP
- **نمایش تدریجی**: روز اول فقط ابزار ساده؛ قابلیت شبکه با استفاده و «لحظهٔ جادویی» (nudge) کشف می‌شود

## طراح مشاهده

- `index.html` را در مرورگر باز کنید — پروتوتایپ تعاملی کامل (۱۷ صفحه، آفلاین، همه‌چیز واقعاً کار می‌کند)
- `overview.html` — سند UX Architecture: مدل سه‌لایه + جدول Keep/Move/Progressive/Enhance/Do-not-remove + ۵ سناریو + نگاشت قواعد بریف
- `png/` — ۱۸ اسکرین‌شات
- `imatch-redesign-3.zip` — بستهٔ کامل برای دانلود یک‌کلیکی
