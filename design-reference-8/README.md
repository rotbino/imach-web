# iMach Design Reference 8 — «قیمتِ زنده» · طرح نهایی

**بیزینس‌مدل طرح ۱ در قالب و زیبایی طرح ۲ — نسخهٔ مرجع بازبینی مالک + ارتقای v2**

طرح ۸ پاسخ مستقیم به جمع‌بندی مالک (اکتبر ۲۰۲۶) است:
> «ساده‌سازیِ طرح ۱ در قالب زیبایی طرح ۲، و بیزینس‌مدل — دنبال‌کردنِ قیمتِ تأمین‌کنندگانِ مختلف توسط یک خریدار — بولدتر و قابل‌فهم‌تر؛ کیف پول دقیقاً جایی که فروشنده اعتبار مصرف می‌کند تا بین دنبال‌کنندگانِ قیمتِ یک کالا بنشیند.»

**v2 (اکتبر ۲۰۲۶):** اجرای کامل UPGRADE-PLAN v2 — ایده‌های جدید مالک پیاده شد: مدل تومانی به‌ازای نتیجه، ذخیره‌کنندگان کاتالوگ، منبعِ رسیدن دنبال‌کنندگان، شیر لیست خرید، «گوش به زنگ»، گزارش کمپین، شارژ درگاه، ثبت‌نام/ورود، درخواست‌های من و پاسخ با قیمت.

**v3 (اکتبر ۲۰۲۶):** «نرخِ منصفانه» + مدیریت کامل — **نرخِ پله‌ایِ صف اول بر اساس ارزشِ کالا** (۴ طبقه؛ درصد با بزرگ‌شدن معامله کم می‌شود — کاربر فقط نرخِ کالای خودش را می‌بیند، منطق پشتِ «چرا این نرخ؟») · **انتخاب جایگاه** (تابلوی تأمین / پیشنهادهای دفتر خریدار) · **توقف کمپین** با برگشتِ بودجه به کیف + راه‌اندازی دوباره · **حالت ویرایش محصول** (فروشنده و خریدار) با آرشیو/حذف دومرحله‌ای. قوانین سخت‌گیرانهٔ طراحی در UPGRADE-PLAN (بخش ۰-۳).

## How to View / نحوهٔ مشاهده

- **دموی تعاملی:** `index.html` را باز کنید (یا روی gh-pages: `design-reference-8/`) — همهٔ دکمه‌ها واقعی کار می‌کنند؛ سوییچ دستیار، شیت‌ها، **راه‌اندازی کمپین تومانی** و **گزارش عددی** را امتحان کنید.
- **نقشهٔ ارتقا:** `UPGRADE-PLAN.md` — هر آیتم R8-U01..U68 با وضعیت اجرا.
- **سند معماری:** `overview.html` — بیزینس‌مدل، میراث، ماتریس صفحات، گالری.
- لوکال: `python3 -m http.server 8898` → `http://localhost:8898`

## بیزینس‌مدل در سه خط (v3)

1. **خریدار** کالا می‌گذارد در لیستش → تابلوی تأمین (چند فروشنده، یک کالا) → قیمت هرکدام را **دنبال می‌کند** (رایگان) → همیشه در دفترش زنده است. لیستش را هم می‌تواند شیر کند — تأمین‌کننده **گوش‌به‌زنگ** می‌شود و اعلام نیاز بعدی را اول خبر می‌شود.
2. **فروشنده** کاتالوکش را شیر می‌کند (مسیر رایگان — هر دنبال‌کنندهٔ تازه **+۵٬۰۰۰ تومان**) یا کمپین **«صف اول»** راه می‌اندازد — **نرخ به ارزشِ کالا وابسته است نه به شخص**: از ۴۰۰ ت/مشاهده برای کالای کوچک تا ۸٬۰۰۰ ت برای خیلی بزرگ؛ هر دنبال‌کردن = ۵ مشاهده؛ درصد با بزرگ‌شدن معامله پله‌ای کم می‌شود. جای نمایش (تابلو/پیشنهادها) را خودش انتخاب می‌کند؛ فقط به خریدارانی نشان داده می‌شود که هنوز دنبالش نمی‌کنند؛ بودجه که تمام شود نمایش می‌ایستد؛ توقف = برگشتِ فورِ پول؛ نتیجه عدد‌به‌عدد در «گزارش کمپین».
3. **رتبهٔ تطبیق هرگز پولی نیست** — صف اول فقط دیده‌شدن می‌خرد و برچسبش شفاف است.

## نکات پیاده‌سازی برای Next.js

- حذف Tabbar یتیم: همهٔ تب‌بارها داخل `.phone` (درس R7) — QA کلیک‌محور
- `data-arm` روی قاب **و body** (شیت‌های خارج از قاب هم رنگ بازویی بگیرند — باگ v1 رفع شد) با CSS متغیر
- state: `{balance, campaign{views,follows,spent,budget,active}, budgetSel, slots{board,feed}, editMode}` — مدل تومانی رویدادمحور + نرخ پله‌ای `TIERS{small,mid,big,huge}` + `GOOD_RATE` (نرخ از کالا، نه شخص)
- مفاهیم جدید برای بک‌اند: **Saver** (ذخیرهٔ کاتالوک، جدای Follow قلمی) · **followSource** (organic/link/promo) · **NeedAlert** (گوش‌به‌زنگ: BUY→کالای لیست) · **CampaignSpend** (رویدادمحور: impression بدون ردی، follow با ۵×) · **WalletToman** (پرداخت درگاه + پاداش دعوت) · **GoodRateTier** (v3: نرخِ هر کالا از «قیمت×حجمِ معمول» همان کالا، کش‌شده — فروشنده وارد نمی‌کند) · **Campaign.placement** (v3: board/feed) · **Campaign.stoppedAt + REFUND** (v3: برگشتِ بودجهٔ مانده)
- نقشهٔ API موجود: `followBuyer` / `offerBuyRequest` / `getMarketState` / `getFollowers` + شکاف‌های پیاده‌سازی در UPGRADE-PLAN
