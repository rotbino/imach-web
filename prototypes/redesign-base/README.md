# iMach — پروتوتایپ تعاملی (redesign-base)

**منبع حقیقت بصری/جریان محصول iMach** — پس از فاز ۵۶: **۲۷ صفحهٔ موبایل + لندینگ دسکتاپ (d3) · ۴۱ شیت · ۶ دیالوگ** (فاز ۵۶: بازگشت نظرات خریداران — نوار «نظر کاربران» لندینگ + صفحهٔ ۴۳ سایر نظرات + مودال ثبت نظر با نقش «فروشنده / تأمین‌کننده‌ام» · ثبت‌نام ۱۶: «کدام دستیار برای کسب و کار شما فعال باشد» دو سوییچر با حداقل-یکی + مودال اینفو (متن عین مالک) · انتخاب صنف: شیت پایین‌رو sheet-snf با جستجو + «ایجاد صنف جدید»، لینک از ۱۶ و ۲۲؛ فاز ۵۵: پیش‌نمایش = آخرین باکس ردیف آمار ۰۱ + حذف چشم از کادر اشتراک با متن جدید مالک · کادر اعلان تازگی عمودی با «اشتراک گذاری برای مشتریان جدید» زیر متن · حذف «پیام آماده» از منو + مخاطبین اول + شیت cshare سه‌حالته (ذخیره‌کرده/عضو/غیرعضو-پیامک) · پیش‌نمایش ۱۳ برای خودِ فروشنده حتی تک‌بازو؛ فاز ۵۴: فرم استعلام ۱۲ سه‌باگ‌فیکس + بج درصد انطباق + درجا-به‌جای-مودال + بازگردانی مدال شرایط؛ فاز ۵۳: سربرگ ظریف ۰۱ + نوار آمار با «دعوت» + صفحهٔ ۵۳ دعوت‌شدگان + QR + نudge قیمت تازه؛ فاز ۵۲: اعتبار قیمت فقط در ۴۴ + سه‌دکمهٔ ویرایش + بج قیمت منقضی).

## معماری رفتاری (خلاصه)

- **دو دستیار** (فروش/خرید) — `ASSIST` با ماندگاری localStorage؛ **ثبت‌نام (۱۶) تک‌بازو (فاز ۵۶)**: «کدام دستیار برای کسب و کار شما فعال باشد» = دو سوییچر (خرید عمده/فروش عمده، حداقل یکی فعال) — فرود روی خانهٔ دستیارِ روشن و پیل «تعویض دستیار» فقط با هر دو روشن. توضیح ریز در مودال آیکون اینفو (متن عین مالک). تغییر بعدی از فرم ۲۲ (ویرایش کسب‌وکار).
- **گارد بازو**: صفحهٔ بازوی خاموش → هدایت به خانهٔ بازوی روشن (`show()`).
- **فوترها**: فروش ۴ تبی · خرید ۳ تبی؛ پروفایل از آواتار هدر → هاب ۴۲.
- **جریان استعلام**: ۱۲ (مودال کالا با قانون لیست خرید + مهلت ۱-۵ + تأمین‌کننده‌ها) → ۴۵ (استعلام‌ها) → ۴۸ (مقایسه) → گفتگو ۱۹؛ سمت فروشنده: ۰۵ → مودال reqview با فرم پیشنهاد همان زیرش.
- **درآمد**: PER_EVENT (بازدید یونیک ۱٬۰۰۰ · ذخیرهٔ کاتالوگ ۳٬۰۰۰ · تماس ۳٬۰۰۰ تومان) + شارژ ۲۹ + تبلیغ ۳۰/۴۶.

## قواعد غیرقابل‌مذاکره طراحی

- **RTL** — تمام رابط فارسی، راست‌به‌چپ
- **IRANSans** — فونت اصلی (فارسی‌نمایی اعداد مهم است)
- **Mobile-first** — دسکتاپ (d3) گسترش همان طرح است
- **هر صفحه یک سؤال جواب می‌دهد** — تراکم اطلاعات ممنوع
- **سادگی = قانون هر فاز** (حکم مالک، فاز ۵۰): «هر قدر ساده‌تر، کاربر بیشتر استفاده می‌کند؛ ولی جوابگوی نیاز واقعی»
- **هیچ حذفی بدون حکم مالک** — همهٔ حذف‌های فاز ۵۰ با حکم صریح انجام شد و در گیت قابل بازیابی‌اند
